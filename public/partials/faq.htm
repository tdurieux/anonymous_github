General

What is Anonymous GitHub?

Anonymous GitHub is an open-source tool with free hosting and optional paid plans that anonymizes GitHub repositories and pull requests for double-anonymous (double-blind) peer review. It replaces identifying information, such as the repository owner, organization name, and custom terms, so that reviewers cannot determine the identity of the authors through the code repository.

How does Anonymous GitHub work?

Anonymous GitHub either downloads the complete repository and anonymizes the content, or proxies requests to GitHub on the fly. In both cases, the original and anonymized versions of files are cached on the server. The system automatically detects and replaces the repository owner, organization name, and repository name. You can also specify additional custom terms to anonymize using one-per-line regex patterns.

What is the scope of anonymization?

In double-anonymous peer review, the boundary of anonymization is the paper plus its online appendix, not the entire internet. Searching for any part of the paper or the online appendix can be considered a deliberate attempt to break anonymity. Anonymous GitHub anonymizes the repository owner, organization, repository name, file and directory names, and file contents across all text-based file types.

How much does it cost?

A free account includes 5 owned repositories and 2 GiB of source files. Optional paid plans offer more capacity, automatic refresh, and, with an author subscription, never-expiring repositories. Reviewers can read shared repositories without an account or payment.

See Plans and billing for available plans and current prices. Offers depend on whether payments are enabled on this instance; the checkout shows the amount before you pay. Subscriptions help fund hosting, storage, backups, and continued maintenance.

You can also support development through GitHub Sponsors or Ko-fi. Donations are separate from subscriptions and do not automatically unlock paid features.

Plans and billing

Why is Anonymous GitHub no longer completely free?

Anonymous GitHub started as a small free service and was paid for out of pocket. Three things have changed since then:

  • Servers cost much more. Every hosted repository needs storage, bandwidth and backups, and these costs have risen sharply.
  • Many more people use it. More users means more repositories to store and keep up to date, more support requests and more maintenance.
  • AI has made security work heavier. AI-driven scrapers and automated abuse send far more traffic than before. Blocking them and keeping hosted content safe takes constant work.

The core service stays free: anonymizing a repository, sharing the link and reviewer access cost nothing, and reviewers never need an account. Most authors never need to pay. The paid options are small one-time payments for one repository, plus an optional subscription for heavy users. They are priced to cover running costs, not to make a profit.

The source code remains open, so you can still host your own instance for free.

What is included in a free account?

The default free allowance is 5 repositories you own and 2 GiB of source files in total. Core anonymization and reviewer access remain free. You can manually refresh a repository within your allowance and choose a dated expiration up to 5 months ahead, then extend it again before it expires. Repositories submitted to a conference can stay online until the end of its review window.

Repositories shared with you as a co-author do not use your own slots. Gists and pull requests are not included in these repository quotas. The usage shown in your account is the allowance available on this instance.

What do monthly and annual author subscriptions include?

Both include 20 owned repositories and 10 GiB of source files in total. They also allow automatic refresh when enabled in repository settings and let the owner choose Never expire.

Monthly and annual plans offer the same features with different billing periods. They renew automatically until you cancel renewal. Current prices are shown in Plans and billing.

Paid plans do not change how anonymization works. File-size limits and other service safeguards still apply. Review your anonymized content before sharing it.

Can I pay for one repository without subscribing?

Yes. These one-time add-ons apply to a single repository you own. None of them renews automatically:

  • Paper pack: an extra repository, automatic updates for 180 days and one more year before it expires, in a single payment. It covers what one paper usually needs during review.
  • Extra repository: host one more repository once your free repositories are used up. It has its own 2 GiB allowance and does not count toward your free repositories. It lasts as long as the repository exists.
  • Live updates: automatic refresh for 180 days, with a separate 2 GiB allowance.
  • Extended expiration: choose an expiration date up to one year after purchase. Buying it again adds another year.
  • Never expire: the repository has no expiration date. A full refund or a payment dispute ends it after a 90-day grace period.

When your free allowance is full, the Extra repository and Paper pack options are offered as you create the repository. You can also buy an add-on from the repository's edit page, or enter the anonymized ID of an existing repository in Plans and billing. Current prices are shown there.

Can a conference or lab pay for a group?

A conference review package provides a shared allowance for a review window of up to 180 days, with automatic updates for every submission. It comes in three sizes: Workshop (25 repositories, 10 GiB), Conference (100 repositories, 50 GiB) and Large conference (400 repositories, 200 GiB). Choose the size when you create the conference; it cannot change afterwards. The organizer pays once and authors pay nothing (the price is shown when you create the conference); the package does not renew automatically. A lab organizing a review can use this shared package too.

New conferences no longer have a free plan: every new conference is a review package. Conferences created earlier keep working as before. The conference must be activated by payment before authors can submit under its Conference ID. Eligible repositories use the conference allowance before an author's personal allowance, so authors do not each need a subscription for that capacity.

The package has a fixed review window. Never expire still requires the repository owner's author subscription or a Never expire add-on for that repository.

Does every co-author need to pay?

No. Co-authors can collaborate without buying a subscription. A shared repository uses its owner's allowance, unless a repository pass or paid conference covers it. It does not consume each co-author's personal allowance.

A co-author's subscription does not increase the owner's allowance. If the owner's available capacity is exhausted, a co-author's refresh or edit may also be blocked. Reviewers never need a paid account.

What counts toward my allowance, and what happens at the limit?

The repository limit counts work you own. Storage counts the source-file sizes reserved for those repositories, not just files a reviewer opens. Archived or failed repositories can still reserve capacity, and a refresh does not automatically reduce a previous storage reservation.

At the repository limit you cannot add another repository to that allowance. An edit or refresh must also fit the available storage. Remove work you no longer need, add an Extra repository for the new one, choose a subscription, or use an eligible conference allowance.

Removing a repository releases its reservation when capacity is next checked. Expired repositories may continue to reserve capacity until cleanup. Reaching a limit does not itself delete existing review links.

What happens to Never expire repositories if I stop subscribing?

Never expire is available to monthly and annual author subscribers, or for one repository with the one-time Never expire add-on. If a subscription ends, these repositories remain available for a 90-day grace period, then expire and their hosted content is removed.

Renewing during the grace period keeps them active. After expiration, you must renew and explicitly reactivate the repository; restoring content also requires access to its GitHub source. A repository does not become public on GitHub when it expires.

Existing never-expiring repositories created before this billing policy retain their settings. Never expire is not a guarantee of perpetual service availability.

How do I cancel, and what happens after paid access ends?

Open Plans and billing and choose Manage billing and invoices to manage renewal. Cancelling renewal keeps subscription benefits until the end of the paid period.

After paid access ends, repositories fall back to another eligible allowance or the free allowance. Automatic refresh pauses on the free allowance; manual refresh remains available within its limits. Existing review links keep their configured expiration dates, except paid Never expire repositories, which follow the 90-day grace period described above.

A repository pass or conference package ends after its paid window without automatic renewal.

Can I get a refund?

Refunds are handled case by case. Email the maintainer with the date of the payment and the repository it was for.

A full refund ends what that payment bought. For a Paper pack, this means all three parts: the extra repository, automatic updates and the extended expiration. A Never expire repository then expires after a 90-day grace period. A partial refund keeps your access.

To stop a subscription, cancel its renewal instead of asking for a refund. You keep access until the end of the period you paid for.

How are payments handled?

Stripe processes checkout and billing management. Anonymous GitHub does not store your card details. You can access billing management and invoices from Plans and billing.

Paid access is activated after payment is confirmed. If checkout succeeds but your account has not updated, choose Refresh payment status before trying another purchase. If paid plans are unavailable on this instance, no checkout is offered.

Features

Which file formats are supported?

Anonymous GitHub can display and render a wide variety of file types:

  • Text and source code: displayed with syntax highlighting
  • Markdown: rendered as formatted HTML
  • Images (PNG, JPG, SVG, etc.): displayed inline
  • PDFs: rendered directly in the browser
  • Jupyter Notebooks: rendered with code cells and outputs

Only text-based files are anonymized. Anonymous GitHub analyzes the content of each file to determine whether it is textual or binary.

Can I anonymize pull requests?

Yes. In addition to full repositories, Anonymous GitHub supports anonymizing individual pull requests. Simply paste the URL of a GitHub pull request when creating a new anonymized repository, and the system will automatically detect that it is a pull request and anonymize it accordingly.

What is the Conference ID feature?

When creating an anonymized repository, you can associate it with a Conference ID. This allows conferences to define default anonymization settings (such as expiration dates) that are automatically applied to repositories submitted under that conference. If your conference provides a Conference ID, enter it during the anonymization setup.

What happens when an anonymized repository expires?

You can configure one of three expiration strategies when creating your anonymized repository:

  • Never expire: with a monthly or annual author subscription, no scheduled expiration while subscribed. A 90-day grace period applies after paid access ends. See the subscription expiration policy.
  • Redirect to GitHub: after expiration, visitors are redirected to the original GitHub repository.
  • Remove content: after expiration, the anonymized content is deleted from the server.

Can I download an anonymized repository?

Yes. Anonymized repositories can be downloaded as a ZIP file. This is useful if reviewers want to build or test the code locally. The downloaded archive contains the fully anonymized version of the repository.

Are updates to the original repository reflected in the anonymized version?

You can refresh the anonymized repository from GitHub without creating a new share link. Free accounts can request a manual refresh within their allowance. Automatic refresh requires an eligible paid allowance and must be enabled in repository settings. It pauses when the repository falls back to the free allowance.

After changing files or contributor names, review your anonymization terms before sharing the updated content. If GitHub access is revoked or the source is deleted, the service cannot fetch updates.

Is there a command-line tool?

Yes. Anonymous GitHub provides a CLI tool that lets you anonymize repositories locally, generating an anonymized ZIP file on your machine. Install it via npm: 

npm install -g @tdurieux/anonymous_github
anonymous_github

Limitations

What are the limitations of Anonymous GitHub?

  • Anonymous GitHub only anonymizes text-based files. Binary files (compiled executables, archives, etc.) are served as-is without anonymization.
  • Files larger than 8 MB are not supported.
  • Static site generators (such as Jekyll) used with GitHub Pages are not fully supported, although Markdown files are converted to HTML.
  • The anonymization of terms within source code may change the behavior of the program (e.g., if a replaced term appears in a string literal or identifier).

Privacy and security

How is my data handled?

Repository data is used to provide the anonymization service. If you purchase a plan, Stripe processes payment and billing information. When a repository is removed or expires, only its configuration is retained. This makes it easy to restore the repository if needed and ensures that no future repository reuses the same ID.

Why does GitHub say Anonymous GitHub asks for write access?

The GitHub App has read-only access to the repositories you choose. You can change repository access on your GitHub connections page.

Legacy GitHub OAuth includes write access to private repositories because GitHub's OAuth scopes do not offer a read-only option for them. Existing OAuth anonymizations and gists can still use this connection.

Anonymous GitHub reads repository content. It never pushes, modifies, or deletes files on GitHub.

Can repository owners see who viewed their anonymized repository?

No. Only the total number of views is tracked as an incremental counter. It is not possible for the repository owner or for Anonymous GitHub to identify individual viewers. Reviewer anonymity is fully preserved.

Self-hosting

Can I deploy my own instance?

Yes. Anonymous GitHub is fully open source (GPL-3.0) and supports Docker-based deployment. Billing is optional and disabled by default for self-hosted instances; paid hosted plans are not required to run your own server. You will need to configure a GitHub OAuth app and provide a GitHub token. Detailed setup instructions are available on the GitHub repository.

The basic steps are:

  1. Clone the repository and install dependencies
  2. Create a .env file with your GitHub token, OAuth client ID, and client secret
  3. Run docker-compose up -d
